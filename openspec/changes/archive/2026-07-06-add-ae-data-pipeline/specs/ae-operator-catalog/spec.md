## MODIFIED Requirements

### Requirement: Operator catalog data file

The system SHALL maintain a static catalog of AE operators in
`src/data/arknights-endfield/operators.ts`, exporting an `AeOperator` interface and a
`const ALL_OPERATORS: AeOperator[]`. The file is auto-generated by
`scripts/update-ae-data.mjs` and SHALL carry the generated-file banner ("do not edit
manually — run the script").

Each entry SHALL have the fields: `id` (string, kebab-case slug, e.g. `chen-qianyu`),
`name` (string, display name), `rarity` (`4 | 5 | 6`), `class` (string, e.g. `Guard`),
`element` (string, e.g. `Heat`), `weapon` (string, e.g. `Greatsword`), and `imageUrl`
(string, local path `/assets/arknights-endfield/operators/{id}.webp`).

#### Scenario: Catalog accessible at runtime

- **WHEN** any component imports `ALL_OPERATORS` from `@/data/arknights-endfield/operators`
- **THEN** the full array of `AeOperator` entries is available with `id`, `name`, `rarity`, `class`, `element`, `weapon`, and `imageUrl` fields

#### Scenario: Entries grouped by rarity

- **WHEN** the catalog is regenerated
- **THEN** entries are grouped 6★ → 5★ → 4★ with a comment banner per group, alphabetical within each group

## REMOVED Requirements

### Requirement: Manual catalog maintenance procedure

**Reason**: Superseded by the automated `ae-data-pipeline` capability. Prydwen's Gatsby
page-data endpoints turned out to expose a fully structured operator list (slug, name,
rarity, class, element, weapon) — the same source the P5X pipeline already consumes —
so the catalog is now regenerated by `scripts/update-ae-data.mjs` instead of edited by
hand.

**Migration**: To add or update an operator, run `node scripts/update-ae-data.mjs` (or
wait for the weekly `update-ae-data.yml` workflow PR). The AE **weapon** catalog
(`weapons.ts`) remains hand-authored per the `ae-weapon-catalog` spec.

### Requirement: Operator portrait seeding

**Reason**: Superseded by the automated `ae-data-pipeline` capability.
`scripts/seed-ae-images.mjs` (hardcoded id array, image upload only) is deleted;
`scripts/update-ae-data.mjs` covers portrait download/resize/upload idempotently via the
shared `ensureAsset` skeleton, deriving image URLs from freshly fetched page-data instead
of hardcoded CDN URL guesses.

**Migration**: Portraits already on ImageKit at `/arknights_endfield/operators/{id}.webp`
remain valid — the update script produces the same 256×256 cover-fit webp output and
skips existing assets. Use `--reupload-operators` / `--reupload-all` to force re-upload.

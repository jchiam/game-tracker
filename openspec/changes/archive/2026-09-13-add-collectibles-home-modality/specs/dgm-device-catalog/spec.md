## ADDED Requirements

### Requirement: Device catalog data file

The system SHALL maintain a static catalog of Digimon digivice / virtual-pet releases in `src/data/digimon/devices.ts`, exporting a `DgmDevice` interface, a `const ALL_DEVICES: DgmDevice[]`, and a `const DGM_LINES: string[]`. The file is generated by `scripts/update-dgm-data.mjs` and SHALL carry the shared generated-file banner.

Each `DgmDevice` SHALL have: `id` (kebab-case slug, unique), `name` (display name including colourway), `line` (product line, open string), `series` (release within the line, open string), `releaseYear` (four-digit integer), `region` (`'JP' | 'NA' | 'EU' | 'ASIA'`), `colorway` (string), and `imageUrl` (local path `/assets/digimon/devices/{id}.webp`). `DGM_LINES` SHALL contain the distinct `line` values in first-appearance order of `ALL_DEVICES`.

#### Scenario: Catalog accessible at runtime

- **WHEN** any component imports `ALL_DEVICES` and `DGM_LINES` from `@/data/digimon/devices`
- **THEN** every entry carries the eight fields above and every `DGM_LINES` value matches at least one entry's `line`

#### Scenario: Entries in seed order

- **WHEN** the catalog is regenerated
- **THEN** `ALL_DEVICES` order equals the seed array order and `DGM_LINES` order equals first appearance within it

### Requirement: Catalog is generated from a hand-authored seed

`scripts/update-dgm-data.mjs` SHALL read `scripts/seeds/dgm-devices.json` — an array of `{ id, name, line, series, releaseYear, region, colorway, imageSource, wikimon? }` where `imageSource` is an http(s) URL, a `wikimon:<File name>` reference resolved to the file's URL through the Wikimon API at run time, or `null`, and `wikimon` optionally names the Wikimon page documenting the row — and SHALL be the only writer of `devices.ts`. The seed is the source of truth and is edited by hand; `src/data/digimon/**` is never hand-edited. The script SHALL compose `scripts/lib/pipeline.mjs` (env loading, ImageKit, `ensureAsset`, `--reupload-*` parsing, catalog diffing, banner) and SHALL NOT copy that plumbing.

#### Scenario: Seed validation rejects bad rows

- **WHEN** the seed contains a duplicate `id`, a missing required field, a `region` outside the enum, or a non-four-digit `releaseYear`
- **THEN** the script exits non-zero naming the offending row and writes nothing

#### Scenario: Images uploaded once through the shared pipeline

- **WHEN** the script runs for an entry whose ImageKit asset already exists
- **THEN** `ensureAsset` reports `skipped` and no download occurs; with `--reupload-devices` the asset is re-fetched from `imageSource` and re-uploaded

#### Scenario: Failed image does not block generation

- **WHEN** an entry's `imageSource` cannot be downloaded
- **THEN** the entry is still emitted with its local `imageUrl`, the failure is listed in the script's missing-assets summary, and the exit code follows the shared pipeline convention for partial failures

### Requirement: External sources inform the seed, never overwrite it

The seed is curated: which releases and colourways count as catalog entries is the collector's decision, so no external source SHALL be the writer of `scripts/seeds/dgm-devices.json`. `scripts/update-dgm-data.mjs --sync-wikimon` SHALL fetch every Wikimon page named by a seed row's `wikimon` field plus Wikimon's `List of Virtual Pets`, and print per page: colourways the seed lacks, seed release years the page does not list, version titles with no seed row, gallery image candidates for rows whose `imageSource` is `null`, and finally the list pages no seed row references. It SHALL NOT modify the seed or `devices.ts`. Content copied from a CC BY-SA source SHALL be attributed in the generated-file banner. Sites whose authors reserve reuse (Humulos / Digitama Hatchery) SHALL NOT be used as a catalog source.

#### Scenario: Sync reports drift only

- **WHEN** `--sync-wikimon` runs and a referenced page lists a colourway or version the seed lacks, or does not list a seed row's release year
- **THEN** the script prints the difference under that page's heading and exits without changing the seed or `devices.ts`

#### Scenario: Wikimon image references resolve at run time

- **WHEN** a seed row's `imageSource` is `wikimon:<File name>`
- **THEN** the script resolves it to the file URL in one batched API call before uploading; a file Wikimon does not have is listed among the missing images and the row is still emitted

#### Scenario: Seed rows stay authoritative

- **WHEN** the seed and a source disagree on a row that the collector has deliberately kept
- **THEN** regeneration emits the seed's values, and the disagreement is only ever surfaced as a report

### Requirement: Manual-dispatch regeneration workflow

The system SHALL provide `.github/workflows/update-dgm-data.yml` triggered by `workflow_dispatch` only (no schedule — the seed changes only by hand), running the script with the ImageKit secrets and opening a pull request with regenerated files, matching the other update workflows' PR mechanics.

#### Scenario: Dispatch opens a regeneration PR

- **WHEN** the workflow is dispatched after a seed change
- **THEN** it runs `scripts/update-dgm-data.mjs` and opens a PR containing the regenerated `devices.ts` if it changed

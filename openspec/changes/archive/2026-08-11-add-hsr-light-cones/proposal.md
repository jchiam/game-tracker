## Why

HSR characters can equip a Light Cone (weapon-analog) that carries meaningful account progression — level and superimposition rank — but the tracker has no record of it. Reverse: 1999 already tracks the equivalent (Psychube) inline on the arcanist card; HSR should reach parity so a character's card reflects its full investment.

## What Changes

- New Light Cone catalog: `src/data/honkai-star-rail/light_cones.ts` (`LightCone { id, name, rarity, path, imageUrl }`), generated by `scripts/update-hsr-data.mjs` from StarRailRes `light_cones.json`, images uploaded to ImageKit.
- Three new columns on `hsr_tracked_characters`: `light_cone_id TEXT`, `light_cone_level INTEGER NOT NULL DEFAULT 1`, `light_cone_superimposition INTEGER NOT NULL DEFAULT 1` (one migration).
- `HsrTrackedCharacter` gains `lightConeId: string | null`, `lightConeLevel: number` (1–80), `lightConeSuperimposition: number` (1–5); `HsrCharacterPatch` mirrors.
- CharacterCard gains an inline "Light Cone" section (psychube-style): summary line `Name · Lv N · S{n}` with "No Light Cone" empty state; edit view with `Select` (filtered to cones matching the character's path — equipping is path-locked in game), `LevelSlider` 1–80, `SegmentedButtons` S1–S5.
- Persistence via plain field updates through `makeFieldUpdater` on the existing roster-persistence column map — no new table, no custom updater.

Out of scope: ascension tracking, light-cone participation in equipment-match scoring, target/preferred light cone in build preferences.

## Capabilities

### New Capabilities

- `hsr-light-cone-catalog`: Static Light Cone catalog shape (id, name, rarity, path, image) and its generation/upload pipeline in `update-hsr-data.mjs`.

### Modified Capabilities

- `hsr-character-detail`: Adds equipped Light Cone tracked fields — selection (path-constrained), level 1–80 with clamping, superimposition 1–5 — plus card summary/edit UI requirements.

## Impact

- **Data**: new generated catalog file; `update-hsr-data.mjs` fetches one more StarRailRes index + image set (ImageKit upload via `ensureAsset`).
- **DB**: one migration on `hsr_tracked_characters`; RLS untouched (existing row policies cover new columns).
- **Code**: `src/types.ts`, `characterService.ts` (column map + select fragment + insert defaults), `useCharacters.ts` (field updaters), `CharacterCard.tsx` + CSS, tests alongside each.
- **No changes** to scoring, parties, build preferences, or other games.

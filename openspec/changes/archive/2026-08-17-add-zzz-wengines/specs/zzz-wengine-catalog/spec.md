## ADDED Requirements

### Requirement: Generated W-Engine catalog

The system SHALL provide a static W-Engine catalog at `src/data/zenless-zone-zero/wengines.ts`, generated by the update script and never hand-edited. Each entry records the Enka item id (string), the loc-resolved English name, the numeric rarity (2/3/4, displayed as B/A/S), the specialty (`ProfessionType` verbatim, same enum as the agent catalog), and a local icon path `/assets/zenless-zone-zero/wengines/{id}.png`. The exported `ALL_ZZZ_WENGINES` array SHALL be sorted rarity descending, then name ascending.

#### Scenario: Catalog entry shape

- **WHEN** the catalog is regenerated from the live Enka store
- **THEN** every entry has a resolvable English name, a rarity in {2, 3, 4}, a specialty matching the agent specialty enum, and an icon path keyed by its item id

#### Scenario: Ordering stable

- **WHEN** two engines share a rarity
- **THEN** they order alphabetically by name within that rarity band

### Requirement: W-Engine icon resolution

`src/lib/imagekit.ts` SHALL expose a W-Engine icon resolver that maps the catalog's local icon path to the ImageKit CDN with a width-128 transform (engine art is already square — no crop), falling back to the raw local path when ImageKit is not configured.

#### Scenario: CDN URL built

- **WHEN** ImageKit is configured and an engine icon path is resolved
- **THEN** the returned URL targets the ImageKit endpoint with a `tr:w-128` transform over `zenless_zone_zero/wengines/{id}.png`

#### Scenario: Fallback without ImageKit

- **WHEN** ImageKit is not configured
- **THEN** the resolver returns the local asset path unchanged

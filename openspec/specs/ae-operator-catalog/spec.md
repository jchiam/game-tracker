## Purpose

Static catalog of Arknights: Endfield operators, consumed at runtime via `ALL_OPERATORS`.
The catalog is auto-generated by `scripts/update-ae-data.mjs` from Prydwen's structured
page-data endpoints (see the `ae-data-pipeline` spec); it was hand-authored in Phase 1
until that source was identified. Operator portraits are uploaded to ImageKit by the same
script.

## Requirements

### Requirement: Operator catalog data file

The system SHALL maintain a static catalog of AE operators in
`src/data/arknights-endfield/operators.ts`, exporting an `AeOperator` interface and a
`const ALL_OPERATORS: AeOperator[]`. The file is auto-generated by
`scripts/update-ae-data.mjs` and SHALL carry the generated-file banner ("do not edit
manually — run the script").

Each entry SHALL have the fields: `id` (string, kebab-case slug, e.g. `chen-qianyu`),
`name` (string, display name), `rarity` (`4 | 5 | 6`), `class` (string, e.g. `Guard`),
`element` (string, e.g. `Heat`), `weapon` (string, e.g. `Greatsword`), and `imageUrl`
(string, local path `/assets/arknights-endfield/operators/{id}.webp`).

#### Scenario: Catalog accessible at runtime

- **WHEN** any component imports `ALL_OPERATORS` from `@/data/arknights-endfield/operators`
- **THEN** the full array of `AeOperator` entries is available with `id`, `name`, `rarity`, `class`, `element`, `weapon`, and `imageUrl` fields

#### Scenario: Entries grouped by rarity

- **WHEN** the catalog is regenerated
- **THEN** entries are grouped 6★ → 5★ → 4★ with a comment banner per group, alphabetical within each group
